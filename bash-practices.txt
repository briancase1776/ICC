Bash Development Practices

How bash is named, laid out and documented. A language skill: it names
no project and no other document.

Scope

This document governs the form of a bash file: what a name looks like,
what the file looks like, and what its documentation block says.

It does not govern how the code works. Nothing here tells you which
construct to reach for, which options to set, how to signal a failure,
or which of bash's traps to avoid. Those are the author's, and a
document that ruled on both would be two documents stapled together.

Where an example here shows code, it is showing a shape, not
prescribing a technique.

Naming Rules

The case against Hungarian is always the same and always wrong the
same way: that a prefix restates a type the compiler already knows,
or that it means nothing in a language with no types. Both make the
language the subject. It is not.

A variable's type is what you put in it and what you use it for. The
language may check that, or not check it, or have no such type at
all, and none of those change what is in the variable. A language
with no void still has functions that return nothing.

So bash having one type, or no floats, or no objects, decides
nothing. Where bash cannot operate on a value the system can. The
prefix names what is held, not who does the sums.

Prefixes

A lowercase prefix, then a capitalised noun. The prefix is everything
up to the first capital, and it is never composed: there is no prefix
for an array of paths. An array's element type is carried by its
noun, as in aPaths or aLines.

Two pairs differ only by case, and the rule resolves them: pIdFile is
a path whose noun is IdFile, pidFile is a process id whose noun is
File. Likewise oRecord and osMessage. Read to the first capital.

- a: Array
  An indexed array, read as "${aLines[@]}". Example: aLines.

- h: Hash
  An associative array, declare -A. Example: hCountByName.

- b: Boolean
  A flag. Say in @details whether it is 0/1 or empty/non-empty.
  Example: bVerbose.

- df: Double-Precision Float
  A decimal value. Example: dfElapsed.

- e: Enumeration
  A value from a closed set. The set is closed by being written down:
  name its members in @details, or spell them as the fixed arms of a
  case. A name that says eThing and leaves the reader to guess the
  members is not an enumeration. Example: eMode.

- fd: File Descriptor
  A descriptor number. Example: fdLog.

- i: Index
  A loop counter or subscript. Example: iLine.

- k: Constant
  A value marked readonly. This is the one row that names how a value
  is declared rather than what it holds, and it overrides the type
  row: a readonly count is kRetries, not nRetries. A k is assigned
  first and marked after, at file scope, and the name is then
  unavailable to any function that would declare it. Example:
  kTimeout.

- n: Integer Number
  A count or size. Example: nRetries.

- o: Object
  A record held as one value, fields to be split out later. Example:
  oRecord.

- os: String
  Text. Example: osMessage.

- p: Path
  A file or directory path, which is bash's only kind of reference.
  Example: pWorkDir.

- pid: Process Id
  Where the value is a process group, the noun says so. Example:
  pidWorkerGroup.

- v: Void
  Functions only. See Function Names.

Naming Usage

- Names fit within 80 columns along with the line they are on.
- UPPER_SNAKE_CASE is reserved for environment variables, read or
  exported.
- Positional parameters are named on the first lines of the file or
  the function, before anything else, and not referred to
  positionally after:
      pSrc=${1:?usage: $0 SRC DST}
      pDst=${2:?usage: $0 SRC DST}
  "$@" is exempt. Inside a function $0 is still the script, so a
  usage line written there names the script and not the function.
- A name a function leaves for its caller is named for what it holds,
  like any other name, and is marked by @global. There is no prefix
  for "global".

Function Names

A function's name carries the prefix of what it puts on STDOUT, and v
where it puts nothing.

    nLineCount()    prints an integer
    pMakeTemp()     prints a path
    vIsReadable()   prints nothing; its status is the answer
    vRotateLog()    prints nothing and is not to be captured

A function that prints nothing is a v whatever it is for, including
one that answers a question. The b row names a variable holding a
flag; it does not name a function, and a function's status is not a
b.

A prefixed name cannot shadow an external command. tee(), sort() and
test() as function names can and do.

Layout

- 80-Column Limit: all code and comments fit within 80 columns.
  Content is never cut to reach it. A comment wraps; a @brief that
  will not fit on one line moves its remainder to @details, which has
  no limit. See Information First.

- ASCII Only: no smart quotes, no em dashes, no box drawing. Where a
  byte is genuinely needed in a string, $'\xNN' is the only spelling
  that does not depend on the environment. $'\uXXXX' and
  $'\UXXXXXXXX' follow the charmap in force at run time: under a
  UTF-8 charmap they encode correctly, and under ANSI_X3.4-1968 --
  which is what LANG and LC_ALL unset, C and POSIX all give, so what
  a script gets from cron, from env -i, and from a bare container --
  they silently emit their own source text instead. $'\uXXXX' also
  takes exactly four hex digits and leaves a fifth as a literal.

- One Command Per Line, with three exceptions: a case arm that fits;
  a brace group sharing one redirection, which is one command; and
  the paired positional naming above.

- Command Substitution: $( ), never backticks.

File Structure

- File Header: #!/bin/bash, then a Doxygen block containing, in
  order: @file, @brief, @details, the contract tags, the copyright,
  the AI contributor line, and the licence reference.

- Licence: reference the licence file. Do not inline its text.

- Copyright Year: append, never replace. 2026 becomes 2026-2027.

Documentation

- Information First: a block earns its place by carrying what the
  code cannot say. NEVER trim content to fit a template, a column, or
  a checker. Where a field is bounded, move the remainder to
  @details, which is not. When tooling and content disagree, the
  tooling is what gets fixed.

- @details is optional and allowed everywhere a block is.

- Doxygen for bash needs four things, and three of them are usually
  missed. In the order that decides whether anything renders at all:

  1. The argument to @file is the BARE FILENAME, never a path.
     Given a path, doxygen reports that the name "is not an input
     file" and discards the block's content on every configuration:
     the brief, the details and the contracts are all absent from the
     generated page, surviving only in the source listing. This one
     line decides more than the other three together.

  2. An INPUT_FILTER that declares each bash function to the C parser
     and blanks the code beneath it. Without it @fn never attaches,
     because the parser glues the preceding statement to the name,
     and the recipe invents members out of bash syntax.

  3. ALIASES for the five tags below, which are not Doxygen commands.
     Note that while 1 is wrong this axis is unreachable and silent:
     doxygen never examines the tags and issues no warning.

  4. EXTENSION_MAPPING, which accepts no_extension as a key, and
     FILE_PATTERNS wide enough to admit extensionless files.

  The five aliased tags: @stdin, @stdout, @stderr, @exit, @global.
  @global takes a name and a direction, and the direction is the
  first word of its description: read, set, or read and set.

  File header:
    #!/bin/bash
    ##
    # @file create
    # @brief One line description.
    # @details Longer description. What the script takes goes here:
    #          a file has no @param to attach one to.
    # @stdin what it reads
    # @stdout what it prints
    # @stderr the reason, on refusal
    # @exit 0 description; 1 description
    #
    # Copyright (c) YEAR HOLDER. All rights reserved.
    # AI contributor: NAME
    #
    # LICENCE. See the project's licence file.
    ##

  Function:
    ##
    # @fn vRotateLog()
    # @brief One line description.
    # @details Longer description if needed.
    # @param $1 pLog - description
    # @stdin what it reads
    # @stdout what it prints
    # @stderr the reason, on refusal
    # @global pLastRotated - set, the path last moved aside
    # @return 0 description; 1 description
    ##

  @return belongs to a function and @exit to a file. A function that
  leaves rather than returns says so in its @return text.

- Section marker, at either level:   ##### section name #####
  Normal inline comment:             # comment

- Bash has no block comment. To disable a region while working use
  : <<'OFF' ... OFF, and do not commit it.
